What Problem Are We Solving?

“

Solar panels produce different amounts of electrical power throughout the day. Their output increases during the morning, usually reaches its highest level around midday, and decreases toward sunset.

However, knowing the power generated at individual moments does not directly tell us how much total electrical energy was produced during the day.

Similarly, a building consumes different amounts of electricity at different times.

Our challenge is to calculate the total energy generated by solar panels, the total energy consumed by the building, and the net energy balance using power readings recorded at regular intervals.

To solve this problem, we use Simpson's 1/3 Rule, a numerical integration technique that estimates the area under a power-versus-time curve.

The Fundamental Physical Relationship:
$$\text{Energy (kWh)} = \int_{t_{\text{start}}}^{t_{\text{end}}} P(t) \, dt \quad \equiv \quad \text{Area under the Power-versus-Time Curve}$$
Where \(P(t)\) is instantaneous power measured in kilowatts (kW) and \(t\) is time elapsed in hours (h). Because SCADA sensors log discrete telemetry samples \(\{P(t_0), P(t_1), \dots, P(t_n)\}\), the exact continuous integral must be evaluated numerically.

Why Can't We Simply Add the Power Readings?

A common misconception in energy auditing is that one can simply take the sum of all instantaneous power numbers recorded by an instrument. This is physically and dimensionally incorrect:

  • Incompatible Physical Dimensions: Instantaneous power readings are measured in kilowatts (kW), which represent the rate of energy transfer at a single split second (\(1\text{ kW} = 1000\text{ Joules per second}\)). Cumulative electrical energy is measured in kilowatt-hours (kWh) (\(1\text{ kWh} = 3.6 \times 10^6\text{ Joules}\)). Summing raw numbers produces \(\text{kW} + \text{kW} + \dots = \text{kW}\), not \(\text{kWh}\)!
  • Accounting for Time Interval (\(h = \Delta t\)): If sensors record readings every 1 hour, every 15 minutes, or every 5 minutes, each reading governs a specific temporal width. Simply adding readings without multiplying by \(\Delta t\) completely distorts the result depending on sampling frequency!
  • Curvature and the Inadequacy of Rectangles: Even if one multiplies by \(\Delta t\) (\(\sum P(t_i) \Delta t\)), that corresponds to a crude Left or Right Riemann rectangle approximation. Because physical solar generation follows a smooth, continuous bell-shaped trajectory, rectangle approximations introduce severe truncation errors. We must account for the continuous time evolution between measurements, which Simpson's 1/3 Rule accomplishes with quadratic (\(\mathcal{O}(h^4)\)) precision.

Why We Chose Simpson's 1/3 Rule

Quadratic Interpolant

Parabolic Approximation

Unlike the Trapezoidal Rule, which connects adjacent readings with straight line chords (linear polynomials, degree 1), Simpson's 1/3 Rule fits a second-degree polynomial (parabola, \(y = At^2 + Bt + C\)) through every triplet of consecutive data points:

$$\int_{x_{2k}}^{x_{2k+2}} P(t) \, dt \approx \frac{h}{3}\left[P(t_{2k}) + 4P(t_{2k+1}) + P(t_{2k+2})\right]$$

Because clear-sky solar irradiance curves exhibit smooth parabolic curvature, quadratic arcs conform to the physical bell curve far better than straight chords.

Fourth-Order Accuracy

Truncation Error & Convergence: \(\mathcal{O}(h^4)\)

The global truncation error of Composite Simpson's 1/3 Rule over \([a, b]\) is strictly bounded by:

$$E_S = - \frac{(b - a) h^4}{180} \, f^{(4)}(\xi), \quad \xi \in (a, b)$$

Because the error decays as \(h^4\), halving the sampling interval reduces the integration error by a factor of \(2^4 = 16\). Furthermore, for any cubic function (\(f^{(4)} = 0\)), Simpson's 1/3 Rule yields the exact analytical integral!

The Composite Simpson's 1/3 Formula

When integrating across \(n\) equal subintervals of width \(h = \frac{b - a}{n}\), the composite quadrature formula is:

$$\int_a^b f(x) \, dx \approx \frac{h}{3} \left[ y_0 + y_n + 4 \sum_{i=1, 3, 5}^{n-1} y_i + 2 \sum_{i=2, 4, 6}^{n-2} y_i \right]$$

⚠️
Why Must the Number of Subintervals \(n\) Be Even?

Each elementary Simpson parabola spans across two adjacent subintervals: \([x_0, x_2]\), \([x_2, x_4]\), \dots, \([x_{n-2}, x_n]\). Therefore, for \(m\) total parabolas, the total number of subintervals must be \(n = 2m\), which is strictly an even integer. Consequently, the number of recorded telemetry observations \(N\) must be odd (\(N = n + 1\)).

Interactive Comparison: Simpson's 1/3 Rule vs. Trapezoidal Rule

Both methods approximate the definite integral of discrete data, but their geometric mechanics differ fundamentally:

Composite Trapezoidal Rule
\(\int_a^b f(x) dx \approx \frac{h}{2} \left[ y_0 + y_n + 2 \sum_{i=1}^{n-1} y_i \right]\)
Polynomial Degree: 1 (Linear) Truncation Error: \(\mathcal{O}(h^2)\) Constraint: Any \(n \ge 1\)

Connects points with straight chords. On concave-down curves (\(f''(t) < 0\)), straight chords lie strictly below the actual curve, creating systematic underestimation.

Composite Simpson's 1/3 Rule
\(\int_a^b f(x) dx \approx \frac{h}{3} \left[ y_0 + y_n + 4 \sum_{\text{odd}} y_i + 2 \sum_{\text{even}} y_i \right]\)
Polynomial Degree: 2 (Quadratic) Truncation Error: \(\mathcal{O}(h^4)\) Constraint: \(n\) must be even

Fits quadratic parabolas across pairs of subintervals. Arches upward along with the natural diurnal solar curve, recovering the area missed by straight trapezoidal chords.

Key Engineering Finding: Notice how the straight trapezoid chord creates a triangular gap below the solar curve, losing \(\approx 0.0667\text{ kWh}\) of generated energy. Simpson's parabolic arch tracks the true curve with high fidelity.

#include <iostream>
#include <iomanip>
using namespace std;

// Simpson's 1/3 Rule
double simpson(double y[], int n, double h) {
    double sum = y[0] + y[n];

    for (int i = 1; i < n; i++) {
        if (i % 2 == 0)
            sum += 2 * y[i];
        else
            sum += 4 * y[i];
    }

    return (h / 3.0) * sum;
}

// Trapezoidal Rule
double trapezoidal(double y[], int n, double h) {
    double sum = y[0] + y[n];

    for (int i = 1; i < n; i++) {
        sum += 2 * y[i];
    }

    return (h / 2.0) * sum;
}

int main() {
    const int n = 12;
    double h = 1.0;

    double gen[n + 1], cons[n + 1], net[n + 1];

    // Input solar generation
    cout << "Enter 13 solar power readings:\n";
    for (int i = 0; i <= n; i++) {
        cin >> gen[i];
    }

    // Input building consumption
    cout << "Enter 13 consumption readings:\n";
    for (int i = 0; i <= n; i++) {
        cin >> cons[i];
    }

    // Calculate net power
    for (int i = 0; i <= n; i++) {
        net[i] = gen[i] - cons[i];
    }

    // Simpson's Rule calculations
    double Egen = simpson(gen, n, h);
    double Econs = simpson(cons, n, h);
    double Enet = simpson(net, n, h);

    // Trapezoidal Rule calculations
    double Tgen = trapezoidal(gen, n, h);
    double Tcons = trapezoidal(cons, n, h);
    double Tnet = trapezoidal(net, n, h);

    cout << fixed << setprecision(4);

    cout << "\n--- SIMPSON'S 1/3 RULE ---\n";
    cout << "Generated Energy: " << Egen << " kWh\n";
    cout << "Consumed Energy: " << Econs << " kWh\n";
    cout << "Net Energy: " << Enet << " kWh\n";

    cout << "\n--- TRAPEZOIDAL RULE ---\n";
    cout << "Generated Energy: " << Tgen << " kWh\n";
    cout << "Consumed Energy: " << Tcons << " kWh\n";
    cout << "Net Energy: " << Tnet << " kWh\n";

    cout << "\n--- DIFFERENCE BETWEEN METHODS ---\n";
    cout << "Generation: " << Egen - Tgen << " kWh\n";
    cout << "Consumption: " << Econs - Tcons << " kWh\n";
    cout << "Net Energy: " << Enet - Tnet << " kWh\n";

    return 0;
}

1. Introduction and Problem Statement

Solar photovoltaic (PV) modules produce varying electrical power throughout the daylight cycle in direct response to solar irradiance, atmospheric clearness, and sun elevation angle. Power output typically initiates at dawn, ascends to a peak around solar noon, and declines toward sunset. Similarly, facility electrical consumption exhibits dynamic temporal variations dictated by operational machinery, ambient lighting, and occupant activities.

Instantaneous power readings are measured in kilowatts (kW), representing the instantaneous rate of energy generation or consumption. However, utility billing, battery storage sizing, and grid-exchange balances depend upon the cumulative electrical energy measured in kilowatt-hours (kWh):

$$E = \int_{t_{\text{start}}}^{t_{\text{end}}} P(t) \, dt$$

Because real-world telemetry systems capture measurements only at discrete sample times, the true continuous power function \(P(t)\) is mathematically unknown. Consequently, analytical calculus cannot be evaluated directly. To solve this problem, numerical integration techniques—specifically Composite Simpson's 1/3 Rule and the Composite Trapezoidal Rule—are applied to compute total generated solar energy (\(E_{\text{gen}}\)), total facility consumption (\(E_{\text{cons}}\)), and the net energy balance (\(E_{\text{net}}\)).

Inaccurate quadrature introduces systematic cumulative errors that compromise economic viability and grid stability.

4. Mathematical Methodology — Simpson's 1/3 Rule and Trapezoidal Rule

Numerical integration approximates the definite integral of a function given only tabulated discrete data points \((t_0, y_0), (t_1, y_1), \dots, (t_n, y_n)\) with uniform spacing \(h = \Delta t\).

4.1 Composite Simpson's 1/3 Rule

Simpson's 1/3 Rule approximates the integrand by fitting successive second-degree Lagrange interpolating polynomials (parabolas) across adjacent pairs of subintervals. Over two consecutive subintervals \([t_{i-1}, t_{i+1}]\), the integral of the interpolating parabola is:

$$\int_{t_{i-1}}^{t_{i+1}} P(t) \, dt \approx \frac{h}{3}\left[P(t_{i-1}) + 4P(t_i) + P(t_{i+1})\right]$$

Summing over an even number of subintervals \(n\) yields the Composite Simpson's 1/3 Rule:

$$E_{\text{simp}} = \frac{h}{3} \left[ y_0 + y_n + 4 \sum_{i=1, 3, \dots}^{n-1} y_i + 2 \sum_{i=2, 4, \dots}^{n-2} y_i \right]$$

The alternating weighting pattern is \(1, 4, 2, 4, 2, \dots, 4, 1\). The global truncation error is given by:

$$E_S = -\frac{(b - a)}{180} h^4 f^{(4)}(\xi), \quad \xi \in [a, b] \implies \mathcal{O}(h^4)$$

Because the error term depends on the fourth derivative \(f^{(4)}\), Simpson's 1/3 Rule is exact for all polynomials up to third degree (cubic).

4.2 Composite Trapezoidal Rule

The Trapezoidal Rule approximates the integrand by linear chords between adjacent sampled points. Over \(n\) subintervals with step size \(h\), the composite formula is:

$$E_{\text{trap}} = \frac{h}{2} \left[ y_0 + y_n + 2 \sum_{i=1}^{n-1} y_i \right]$$

The weighting pattern is \(1, 2, 2, \dots, 2, 1\). The global truncation error is:

$$E_T = -\frac{(b - a)}{12} h^2 f''(\xi), \quad \xi \in [a, b] \implies \mathcal{O}(h^2)$$

4.3 Method Comparison & Rationale for Solar Analysis

Photovoltaic generation curves feature smooth, continuous physical curvature characterized by a negative second derivative (\(P''(t) < 0\)) during peak daylight hours. Because linear secant chords cut strictly beneath a concave-down curve, the Trapezoidal Rule systematically underestimates total solar generation. In contrast, Simpson's 1/3 Rule preserves second-order curvature, effectively recovering the peak solar energy harvest.

C++ Implementation

The following C++ program implements Composite Simpson's 1/3 Rule and the Trapezoidal Rule to calculate total solar energy generation, building energy consumption, and net electrical energy from discrete power measurements. 

#include <iostream>
#include <iomanip>
using namespace std;

// Simpson's 1/3 Rule
double simpson(double y[], int n, double h) {
    double sum = y[0] + y[n];

    for (int i = 1; i < n; i++) {
        if (i % 2 == 0)
            sum += 2 * y[i];
        else
            sum += 4 * y[i];
    }

    return (h / 3.0) * sum;
}

// Trapezoidal Rule
double trapezoidal(double y[], int n, double h) {
    double sum = y[0] + y[n];

    for (int i = 1; i < n; i++) {
        sum += 2 * y[i];
    }

    return (h / 2.0) * sum;
}

int main() {
    const int n = 12;
    double h = 1.0;

    double gen[n + 1], cons[n + 1], net[n + 1];

    // Input solar generation
    cout << "Enter 13 solar power readings:\n";
    for (int i = 0; i <= n; i++) {
        cin >> gen[i];
    }

    // Input building consumption
    cout << "Enter 13 consumption readings:\n";
    for (int i = 0; i <= n; i++) {
        cin >> cons[i];
    }

    // Calculate net power
    for (int i = 0; i <= n; i++) {
        net[i] = gen[i] - cons[i];
    }

    // Simpson's Rule calculations
    double Egen = simpson(gen, n, h);
    double Econs = simpson(cons, n, h);
    double Enet = simpson(net, n, h);

    // Trapezoidal Rule calculations
    double Tgen = trapezoidal(gen, n, h);
    double Tcons = trapezoidal(cons, n, h);
    double Tnet = trapezoidal(net, n, h);

    cout << fixed << setprecision(4);

    cout << "\n--- SIMPSON'S 1/3 RULE ---\n";
    cout << "Generated Energy: " << Egen << " kWh\n";
    cout << "Consumed Energy: " << Econs << " kWh\n";
    cout << "Net Energy: " << Enet << " kWh\n";

    cout << "\n--- TRAPEZOIDAL RULE ---\n";
    cout << "Generated Energy: " << Tgen << " kWh\n";
    cout << "Consumed Energy: " << Tcons << " kWh\n";
    cout << "Net Energy: " << Tnet << " kWh\n";

    cout << "\n--- DIFFERENCE BETWEEN METHODS ---\n";
    cout << "Generation: " << Egen - Tgen << " kWh\n";
    cout << "Consumption: " << Econs - Tcons << " kWh\n";
    cout << "Net Energy: " << Enet - Tnet << " kWh\n";

    return 0;
}
